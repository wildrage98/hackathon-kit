# 실무자(담당자) 에이전트 인터뷰 — 순서와 질문 묶음

평가 3축 중 **Intent(문제 정의·지시 품질)**가 가장 변별력이 컸다(코파톤 후기). 인터뷰 대화 자체가
채점 자료다. 질문은 **3~5개씩 묶어** 보내고(응답 대기 시간 절약), 답은 즉시 `docs/QUESTIONS.md` 하단 표에 옮긴다.

## 0. 시작 전 3분: README를 먼저 다 읽는다
코파톤 참가자 후기: README에 문제가 이미 자세히 적혀 있었고, 질문해도 README 내용이 반복됐다.
→ README에 있는 걸 묻지 않는다. README의 **빈칸**을 찾아 묻는다.

## 1. 1차 질문 묶음 (0~8분) — 목표·사용자·범위
```
안녕하세요, 개발을 맡은 OOO입니다. 시작 전에 몇 가지 확인드립니다.
1) 이 결과물을 실제로 쓰는 분은 누구이고(운영자/엔지니어/관리자), 하루 중 언제 어떻게 보나요?
2) 지금은 이 일을 어떻게 처리하고 계신가요? (수작업? 엑셀? 기존 시스템?) 그 방식의 가장 큰 불편은요?
3) 최근에 실제로 문제가 됐던 사례 하나만 구체적으로 들려주실 수 있을까요? (언제, 어떤 설비, 무슨 일)
4) 오늘 180분 안에 반드시 되어야 하는 것 3가지와, 되면 좋은 것을 나눠주세요.
5) 명시적으로 하지 않아도 되는 것(실설비 연결, 실시간, ML, 로그인 등)은요?
```
→ 3번(에피소드)이 핵심. 성공 기준의 "현재값"이 여기서 나온다 (예: "월 2회 놓침, 발견까지 40분").

## 2. 2차 질문 묶음 (8~15분) — 데이터·기준 (profile 결과를 들고)
`python -c "from kitlib import csvio, profile; ..."` 또는 `tools/profile_csv.py data/x.csv` 결과를 보고 묻는다.
```
데이터를 훑어봤습니다. 확인 부탁드립니다.
1) 컬럼 X의 단위와 정상 범위는요? (관측 min~max는 a~b였습니다)
2) 컬럼 state 값 RUN/IDLE/MAINT 중 판정에서 제외할 상태가 있나요?
3) 결측이 c% 있는데 수집 실패인가요, 해당 없음인가요? 제가 '표시만 하고 판정 제외'로 처리해도 될까요?
4) 샘플링 주기가 d초로 보이는데, 몇 배 이상 끊기면 '수신 장애'로 볼까요? 장애 자체를 경보로 볼까요?
5) 정상 기준을 수치로 주실 수 있나요? 없다면 제가 정상 구간 데이터로 제안 드리고 확정받겠습니다.
```
`kitlib.profile.questions_from_profile()` 이 이런 질문 후보를 자동 생성한다.

## 3. 기준이 없을 때의 제안 화법 (Intent 점수)
```
정상 기준이 문서로 없다고 하셨으니, 제가 다음과 같이 잡겠습니다:
- 설비별로 RUN 상태 앞 1/3 구간을 기준 구간으로 보고 IQR 2배를 WARN, 4배를 CRIT로 제안합니다.
- 단발 초과는 WARN 확정 안 하고 2회 연속일 때 확정, 정상 1분(6샘플) 지속 시 해제.
이대로 진행해도 될까요? 다른 기준이 있으면 그 값으로 바꾸겠습니다.
```
답이 오면 그대로 `config/rules.json`과 AGREEMENT.md에 적는다. **담당자가 "네"라고 한 기록**이 근거다.

## 4. 합의서 (docs/AGREEMENT.md) — 빌드 전에 담당자 확인
코파톤에서 요구된 형식. 담당자 에이전트에게 통째로 보내 "맞습니까?"를 받는다.
```
[합의서 초안] 확인 부탁드립니다. 틀린 부분만 지적해 주세요.
문제: (한 문장)
원인/배경: (현재 방식과 불편)
성공 기준: (측정 가능, 현재값 → 목표값, 데이터 출처)
만드는 것: 1) 2) 3)
만들지 않는 것: 1) 2)
가정/제약: (데이터 주기, 기준값 출처, 환경)
검증 방법: (합성 데이터 심기, 예시 케이스 일치, 경계값 테스트)
```

## 5. 중간 체크인 (60분, 120분)
```
중간 보고입니다. 현재 1) 2) 가 동작하고, 3)은 진행 중입니다.
확인 1개: (구현 중 생긴 애매한 점 — 예: 중복 행의 값이 다를 때 어느 쪽을 믿을까요?)
남은 시간 고려해 4)는 '정책만 문서화'로 축소하려 합니다. 괜찮을까요?
```
→ 범위 축소를 **담당자와 합의한 기록**이 있으면 미구현이 감점이 아니라 판단이 된다.

## 6. 하지 말 것
- 해결책부터 말하기("대시보드 만들겠습니다") — 먼저 문제·사용자·기준
- 한 번에 15개 질문 — 3~5개 묶음, 답 보고 다음
- 답을 안 적고 넘어가기 — QUESTIONS 표 + AGREEMENT
- 담당자가 모른다는 걸 계속 캐묻기 — "그럼 제가 X로 가정하고 문서에 적겠습니다"로 닫는다
