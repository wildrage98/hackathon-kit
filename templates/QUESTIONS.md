# QUESTIONS — 요구사항 협의 체크리스트

담당자 에이전트에게 물어 답을 채운다. 답이 없는 항목은 **내가 제안해서 확정받는다** ("~로 하겠습니다. 괜찮습니까?").
확정된 기준은 그대로 PLAN.md의 "확정 요구사항"과 AGREEMENT.md로 옮긴다.
유형별 추가 질문은 hackathon-kit/playbook/0N-*.md 의 '담당자 인터뷰 추가 질문' 참고. 질문은 3~5개씩 묶어 보낸다.

## A. 목표·범위
- [ ] 이 시스템의 1차 사용자는 누구인가? (운영자/엔지니어/관리자) 어떤 상황에서 쓰는가?
- [ ] 반드시 되어야 하는 것 3개는? 되면 좋은 것은?
- [ ] 명시적으로 **범위 밖**인 것은? (실설비 연결, 실시간성, ML, 인증 등)
- [ ] 제출 필수 파일명·형식·위치가 정해져 있는가?
- [ ] 평가 시 무엇을 실행해 보는가? (CLI? 웹 화면? 특정 입력 파일?)

## B. 데이터
- [ ] 입력 형식 (CSV/JSON/스트림), 파일 수, 대략 행 수
- [ ] 컬럼 목록과 단위, 타임스탬프 형식·타임존·샘플링 주기
- [ ] 대상(설비/장치/라인)별로 스키마가 다른가? 식별자는 무엇인가?
- [ ] 샘플 데이터를 받을 수 있는가? 없으면 내가 합성 데이터를 만들어도 되는가?
- [ ] 알려진 데이터 품질 문제: 결측 / 중복 / 시간 역전 / 수신 끊김 / 이상값(센서 고장) / 단위 불일치

## C. 판단 기준 (핵심)
- [ ] 정상 기준이 문서로 있는가? (대상별 정상 범위, 임계치)
- [ ] 운영 상태(가동/대기/정비/워밍업)가 구분되는가? 상태별로 기준이 다른가? 상태는 데이터에서 어떻게 아는가?
- [ ] "이상"의 정의: 단발 초과 / N초 지속 / 추세 변화 / 복합 조건?
- [ ] 등급이 있는가? (주의/경고/위험) 등급 간 기준은?
- [ ] 경보 시작·변경·해제 조건은? 해제 후 재발 시 새 경보인가?
- [ ] 오탐과 미탐 중 어느 쪽이 더 비싼가? (민감도 방향)
- [ ] 판단 근거로 무엇을 보여줘야 하는가? (어떤 값이, 어떤 기준을, 언제부터)

## D. 운영·화면
- [ ] 결과를 어떻게 보는가? (콘솔/파일/웹 화면) 웹이면 최소 기능은?
- [ ] 과거 조회가 필요한가, 현재 상태만 보면 되는가?
- [ ] 이력(경보 로그)을 파일로 남겨야 하는가? 형식은?
- [ ] 운영자가 기준을 바꿀 수 있어야 하는가? (설정 파일로 충분한가)

## E. 검증·평가
- [ ] 정답 라벨이 있는 데이터가 있는가? 없으면 어떤 방식의 검증을 인정하는가?
- [ ] 재현성 요구: 같은 입력 → 같은 출력이면 되는가? 실행 명령 하나로 재현 가능해야 하는가?
- [ ] 성능(처리 시간·용량) 요구가 있는가?

## F. 환경
- [ ] 허용 언어·라이브러리 제약 (설치 가능 여부)
- [ ] 포트·실행 방식 제약
